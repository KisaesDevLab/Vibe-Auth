## 1. Decisions

1. **Staff realm only.** Recipient and client portals (capability tokens + OTP + TIN) are untouched (I11); their routers stay mounted before the engine.
2. **Roles.** Vocabulary `["admin","reviewer","preparer"]`, `adminRole: "admin"`; map `vibe-admin`/`vibe-it`/`vibe-partner` → `admin`, `vibe-manager` → `reviewer`, `vibe-staff` → `preparer`.
3. **Firm.** Single-firm deployment; JIT users join the only firm (`bootstrapFirm`'s). Unique `(firm_id, email)` makes email linking safe.
4. **Session adapter.** `create` = Redis `createSession` + set `v1099_sid` and `v1099_csrf` exactly as `routes/auth.ts:76`; identity → `auth_sessions_oidc` in Postgres (Redis holds no identity data); `destroyByIdentity` → `destroyAllUserSessions`. TOTP: an SSO session skips local TOTP (the IdP's MFA stands in; set `VIBE_OIDC_REQUIRE_MFA_AMR=true` in the env template).
5. **Cookie `secure`** is derived from `APP_BASE_URL` scheme; on the LAN box `APP_BASE_URL` is `http://<ip>...` so it is false, correct. Keep `ALLOW_HTTP_BASE_URLS=1` in the appliance env template (the prod interlock otherwise refuses http).
6. **Mount order (I3):** after `/api/portal`, `/api/w9-public`, `/api/client-portal`, `/api/webhooks/taxbandits` and `staffIpAllowlist` (`app.ts:94-101`), before the staff router (`:102`). The back-channel POST arrives from `vibe-auth-authentik-server` on `vibe_net`; either allowlist the docker network in `STAFF_IP_ALLOWLIST` or exempt `/auth/oidc/backchannel` in `staffIpAllowlist()`.
7. **CSRF.** The package's routes are outside `requireStaff`, so the double-submit check does not apply to them. The settings page `fetch` adds `x-csrf-token` from the cookie (`api.ts:17`).
8. **No base path, two containers** → SPA is root-served on its own host (the console manifest has a subdomain), so `basePath: ""` everywhere and a `/auth/*` matcher to `vibe1099-app:8210`.
9. **tsx runtime:** adapter stays TypeScript. `breakglassCommand: ["pnpm","--filter","@vibe1099/api","exec","tsx","node_modules/@kisaesdevlab/vibe-auth/dist/cli.js","breakglass","ensure","--json"]`; `"vibeAuth": { "adapter": "./src/vibeAuthAdapter.ts" }` in `apps/api/package.json`. Verify in the image as `USER node` (README lesson 7).

## 2. Steps

**A.** Dependency in `apps/api/package.json`, `.npmrc`, BuildKit secret in `Dockerfile.node` around `pnpm install`. SQL migration in `packages/db` migrations: package SQL + `auth_sessions_oidc`.

**B.** `apps/api/src/lib/vibeAuthUsers.ts`: argon2id unusable hash (`ARGON_OPTS` from `routes/auth.ts:23`), `active` for `setActive`; audit → `audit()` (`packages/core/src/audit.ts:27`).

**C.** `apps/api/src/lib/vibeAuth.ts`: session adapter per §1.4; `secretWrap` via `packages/core/src/crypto.ts` (`MASTER_KEY` HKDF→KEK AES-GCM); stores on the pg pool.

**D.** Wiring per §1.6; `guardLocalLogin` on `POST /api/auth/login` (`:34`) keeping the rate limiter and lockout in front; `afterLocalLogin` on success; `await auth.start()` in `apps/api/src/index.ts`.

**E.** SPA: `staff/Login.tsx` `<LoginPanel basePath="" returnTo="/">`; `/login/local` route in `main.tsx:34-39` public list; settings tab `authentication` in `Settings.tsx:59` rendering `<AuthSettingsPage basePath="" productName="1099" fetch={apiWithCsrf}>`; sign-out → `/auth/oidc/logout?local=1` when SSO-born (expose on `/api/auth/me`).

**F.** Manifests: create `.appliance/manifest.json` from the console one (retire `appliance/manifest.yaml` or mark legacy); add to both:

"requires": ["identity"],
"routing": { "default_upstream": "vibe1099-web:8211",
  "matchers": [ { "name": "api", "path": "/api/*", "upstream": "vibe1099-app:8210" },

"sso": { "capable": true, "redirectPaths": ["/auth/oidc/callback"], "logoutPaths": ["/auth/oidc/backchannel"],
  "publicPaths": ["/api/health","/api/about","/api/status","/api/portal/*","/api/w9-public/*","/api/client-portal/*","/api/webhooks/taxbandits","/api/auth/login","/api/auth/password-reset/*","/f/*","/w9/*","/client","/client/*"],

  "breakglassService": "vibe1099-app",

**G.** Tests: `test/sso-e2e.mjs`; add supertest to `apps/api` devDeps and write the first HTTP-level auth tests: callback sets both cookies; a staff POST with the csrf from the cookie succeeds; portal token routes unaffected in `oidc_only`; back-channel ends Redis sessions.
