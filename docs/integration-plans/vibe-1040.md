## 1. Decisions

1. **The MFA gate is the design decision.** `requireUser` demands `mfa_satisfied_at`. An SSO session must arrive satisfied or the user is deadlocked (the MFA endpoints assume a local factor). Rule: **`VIBE_OIDC_REQUIRE_MFA_AMR=true` is mandatory for this product** (env template default, and the engine refuses to create a session whose `amr` lacks a second factor). `SessionAdapter.create` = `issueSession` + `satisfyMfa(sessionId)` in one step. Document the GLBA/§11 argument in `docs/sso.md`: the IdP's enforced MFA stands in for the local factor, and the audit row records `amr`.
2. **Mount point.** Register `formbody` + `vibeAuthFastify` in `buildServer()` before `registerRoutes` (`:62`) and add `/auth` to the SPA not-found exclusion (`:66-69`) so `/auth/oidc/callback` is never `index.html`. `attachUser` (global `preHandler`) is harmless on `/auth/*`.
3. **Roles.** Vocabulary `["admin","partner","staff"]`, `adminRole: "admin"`; map `vibe-admin`/`vibe-it` → `admin`, `vibe-partner` → `partner`, `vibe-manager`/`vibe-staff` → `staff`. `setActive(false)` sets `disabledAt`.
4. **JIT users** get `mfaMethod: 'totp'`, no secret, `mfaEnrolledAt: null`; they never hit local MFA because their sessions are SSO-satisfied. If such a user later logs in locally (mode `both`), the normal enrolment flow runs, which is correct.
5. **Cookie flags stay** (`strict`, `SESSION_SECURE`).
6. **Public URL.** The product has no origin env; the appliance's identity script derives the registration base from `ALLOWED_ORIGIN` + `VITE_BASE_PATH` in the product env. For a root-served app in LAN mode that is `http://<ip>:5177` (emergency port; `enable-app.sh` renders it so) and `https://1040.<domain>` in domain mode. Add `ALLOWED_ORIGIN` to the env template as a declared-but-unread key so the derivation has a source (the same trick Calculators relies on). Redirect URIs then come from `VIBE_OIDC_PUBLIC_URL`; the engine uses `basePath: ""`.
7. **Standalone installs** (own compose): register with the broker by hand (`docs/sso.md`, TB's "Registration" section).
8. **Break-glass:** `["node","node_modules/@kisaesdevlab/vibe-auth/dist/cli.js","breakglass","ensure","--json"]` from `/app`; adapter `dist/vibeAuthAdapter.js`. The break-glass user is local and *must* satisfy local MFA to pass `requireUser`; provision it with `mfaMethod: 'totp'` and print the TOTP enrolment as part of `breakglass ensure` output, or, simpler and preferred, mark break-glass sessions MFA-satisfied at password login (the account has no second factor by design, D12) and audit it. Decide in the PR; the plan prefers the latter.
9. **Boot dependencies** (`VIBE_AI_TOKEN`, region assert) are unrelated to SSO; `auth.start()` runs after them.

## 2. Steps

**A.** Dependency (`package.json` `^1.0.3`, `.npmrc`, BuildKit secret in `Dockerfile`). Drizzle migration: package SQL + `sessions` OIDC columns.

**B.** `src/lib/vibeAuthUsers.ts`: scrypt unusable hash via `src/auth/credentials.ts`; audit → `audit()` (`src/audit/log.ts:80`; extend the closed action union with `vibe.auth.*`).

**C.** `src/lib/vibeAuth.ts`: Fastify session adapter (`reply.setCookie` with `sessionCookieOptions`), `create` = issue + satisfy; `destroyByIdentity` = `revokeSession` on matching rows; `secretWrap` via `src/storage/index.ts:22-33` (`STORAGE_ENCRYPTION_KEY` AES-GCM); stores on the `pg` pool.

**D.** Wiring per §1.2; local-login guard as a `preHandler` on `POST /api/auth/login` (`routes.ts:87`) returning the product's envelope; `afterLocalLogin` after the password check; `await auth.start()` in `src/server.ts` after `assertUsRegionPinning`.

**E.** SPA: `<Login>` in `ui/src/App.tsx:103-124` wraps the form with `<LoginPanel basePath="" returnTo="/">`; add views `login-local` (break-glass) and `auth-settings` (admin tab in `ui/src/components/Admin.tsx:12-39`); after the callback the SPA lands signed in and satisfied, so `api.me` moves straight to `bundles`. Sign-out → `/auth/oidc/logout?local=1` when SSO-born.

**F.** Manifests: create `.appliance/manifest.json` from the console one; add to both:
```jsonc
"requires": ["identity"],
"sso": { "capable": true, "redirectPaths": ["/auth/oidc/callback"], "logoutPaths": ["/auth/oidc/backchannel"],
  "publicPaths": ["/health","/api/auth/login","/api/auth/forgot","/api/auth/reset","/api/auth/mfa/*","/api/auth/totp/*","/api/auth/factor","/api/auth/logout"],
  "edgeGate": false, "internalUrl": "http://vibe-1040:8240",
  "breakglassService": "vibe-1040",
  "breakglassCommand": ["node","node_modules/@kisaesdevlab/vibe-auth/dist/cli.js","breakglass","ensure","--json"] }
```
Env template: `VIBE_OIDC_REQUIRE_MFA_AMR=true`, `ALLOWED_ORIGIN` (subdomain-url).

**G.** Tests: first HTTP-level tests via `buildServer().inject()`: callback with `amr=[pwd,otp]` yields a satisfied session and `requireUser` passes; callback with `amr=[pwd]` is refused; back-channel revokes; `test/sso-e2e.mjs` with the fake IdP configured to emit `amr`.

**H.** `docs/sso.md` (MFA rationale, standalone registration); PR `(Phase 8 step 9)`.
