- Reference compose has **server, worker, postgresql only — no Redis** (Q5 → no external cache required). `vibe-auth-cache` dropped from §2.1.
- `AUTHENTIK_WEB__PATH` provides **subpath deployment** ("must contain leading and trailing slash") — contradicts the premise of D9 ("Authentik does not support subpath deployment"). See QUESTIONS Q7. Verified live: with `AUTHENTIK_WEB__PATH=/auth/` the API (`/auth/api/v3/`), flows (`/auth/if/flow/…`), OIDC endpoints (`/auth/application/o/<slug>/…`) and static assets all serve under the prefix; the admin `authenticators/admin/totp/` endpoint is list/delete only (no create), so the integration test enrols MFA through the real flow.
- Bootstrap env `AUTHENTIK_BOOTSTRAP_PASSWORD|TOKEN|EMAIL` apply on first start only and act on `akadmin`; the token is usable as an API bearer immediately.
- OAuth2 provider: `redirect_uris` is a list of `{matching_mode: strict|regex, url}`; `issuer_mode` `per_provider` (default) → issuer `https://host/application/o/<slug>/`; `logout_uri` + `logout_method: backchannel|frontchannel` on the provider (back-channel logout token carries `iss, sub, aud, iat, jti, events, sid`; sent on user logout, admin session delete, user deactivation, session expiry). Blueprints apply atomically from `/blueprints/*.yaml` with `!Find`, `!KeyOf`, `!Env` tags.

## D. Amendments to §2 (mirrored into the build plan)

1. **§2.1** — remove `vibe-auth-cache` (no Redis in Authentik ≥2025.x). Add the manifest-driven Appliance expectations: no host ports from the overlay; emergency port **5180** reserved for the broker admin UI.
2. **§2.2** — the manifest schema has no `provides`/`requires`. Phase 6 **adds** `provides: string[]` and `requires: string[]` (soft: install-order only) plus the `sso` block to `console/manifest.schema.json`; `requiredApps` stays hard. `depends` gains no new values. `ownsInfra: ["identity"]` is set on `vibe-auth` and `sameProductAs`-style conflict handling with `sentinel-core` is a QUESTIONS item (Q8).
3. **§2.3** — locks D15: the console writes the `VIBE_OIDC_*` block with `secrets_set_kv_per_app` (or a `from: "vibe-auth:registration"` env entry rendered by `_render_app_env`) and then runs `_settings_restart_app`-style `up -d --force-recreate --no-deps` on that product. `VIBE_AUTH_MODE` is never written by the console (D11). Break-glass provisioning uses `docker exec <product> npx vibe-auth breakglass ensure` (unchanged).
4. **§2.4** — there is no snippet import mechanism. `deploy/caddy.snippet` is replaced by: (a) manifest `routing` for the broker (path-mounted at `/vibe-auth/` like every other app), and (b) Phase 6 changes to `lib/render-caddyfile.sh` to emit the Authentik vhost/handler per mode. Routing per mode: `domain/subdomain-per-app` → `auth.{host}`; `domain/single-host` and `lan` → **subpath `/auth/`** via `AUTHENTIK_WEB__PATH=/auth/` (pending Q7 decision; port `:8443` kept available as `VIBE_AUTH_ROUTING=port` fallback exactly as D9 specifies); `tailscale` → `auth.{ts-host}` is impossible (one hostname per node), so subpath there too. The edge gate stays opt-in (D10) and is emitted by the renderer when `sso.edge_gate=true`.
5. **§2.5** — Vibe Backup has no restore ordering. `deploy/backup.contract.yaml` declares `vibe_auth` DB + `vibe-auth-media` and a `post_restore` hook that calls `/rebase` + `/registrations/verify`. Cross-module order (Postgres → vibe-auth → products) is documented in the runbook; implementing it in Vibe Backup is out of scope (Q9).
6. **§2.6** — `end_session_endpoint` is browser-facing and is **not** rewritten to the internal base (only `token`, `jwks`, `userinfo`, `revocation`, `introspection` are). `VIBE_OIDC_INTERNAL_BASE` is an **origin** (`http://vibe-auth-authentik-server:9000`); the issuer path already carries `/auth/…`. Because authentik derives the per-provider issuer from the request host, the client sends `X-Forwarded-Host`/`X-Forwarded-Proto` (public values) on every internal call — verified against authentik 2026.8.2 in `test/scripts/integration.mjs`. `VIBE_OIDC_PUBLIC_URL` is the product base **including** its path prefix.
7. **§2.7** — cache limits removed; totals: server 1 GB, worker 768 MB, broker 256 MB.
8. **§2.8** — unchanged.
9. **D3/D4 "Express middleware"** — AI Router, Recap and 1040 are Fastify 5. The client package ships a framework-neutral engine with Express and Fastify adapters. Backup (Go) is out of the package's reach; its admin UI is protected by the console proxy, which becomes an SSO consumer itself (Q10).
